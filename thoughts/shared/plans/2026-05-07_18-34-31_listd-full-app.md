# Listd - Native Flutter To Do App Implementation Plan

## Overview

Build a native Flutter To Do application with Google Tasks integration for Linux desktop (with cross-platform support). Architecture uses Material 3 with Indigo (#5C6BC0), Riverpod for state management, drift for SQLite caching, go_router for navigation, and OAuth2 PKCE via the oauth2 Dart package for Google authentication. The ITaskProvider interface enables provider-agnostic design allowing future local-only or alternate cloud providers.

## Desired End State

```dart
// User launches app
void main() {
  runApp(
    ProviderScope(
      child: MaterialApp.router(
        theme: AppTheme.lightTheme,
        darkTheme: AppTheme.darkTheme,
        routerConfig: appRouter,
      ),
    ),
  );
}

// User authenticates with Google
final authService = ref.read(googleAuthServiceProvider);
await authService.authorize(); // Opens browser for OAuth

// User sees their task lists
final taskLists = await ref.read(taskListsProvider.future);
// Displays in UI with Riverpod AsyncValue pattern

// User creates a task
await ref.read(createTaskProvider(taskListId, task).future);
// Saves to local drift DB, syncs to Google Tasks API
```

## What We're NOT Doing

- Offline editing (read-only cached mode per discover spec)
- Infinite scroll pagination (fetch all tasks)
- Advanced conflict resolution (last-write-wins only)
- Testing infrastructure (deferred to implementation phase)

## Performance Considerations

- **Drift on Linux**: Use compute() for heavy queries to prevent UI blocking
- **Token refresh**: Silent refresh before expiry to avoid UI wait
- **Initial load**: Fetch task lists and tasks on app start, cache in drift
